# СОЮЗ-ПРИБОР • AI-помощник для подготовки карточек товаров КИПиА

Прототип сервиса автоматической подготовки черновиков карточек товаров контрольно-измерительных приборов и промышленной автоматики (КИПиА) для B2B-интернет-магазина [СОЮЗ-ПРИБОР](https://www.souz-pribor.ru/).

Разработано в рамках тестового задания на позицию **AI-разработчик**.

---

## 1. Возможности и соответствие требованиям

- **Входные форматы:** прием данных в формате JSON через REST API или интерактивную веб-форму.
- **Интеграция с LLM:** поддержка любых OpenAI-совместимых провайдеров (OpenAI, Groq, OpenRouter, Ollama, YandexGPT) с возможностью переключения моделей через переменные окружения.
- **Встроенный Zero-Key режим (Deterministic Offline Engine):** сервис запускается и полностью функционирует даже **без внешних API-ключей**, формируя качественные и строгие черновики для моментального тестирования проверяющим.
- **Полная структура требуемого результата:**
  - **SEO-заголовок (title):** строго до 70 символов с валидацией длины.
  - **SEO-описание:** связный технический текст объемом строго **800–1200 символов** без «воды».
  - **Структурированный список ключевых характеристик:** строгая привязка к паспортным данным изделия.
  - **3–5 поисковых запросов:** коммерческие B2B-запросы для продвижения страницы.
  - **Commercial-блок для менеджера по продажам:** целевая аудитория, прикладные задачи и выгоды заказчика.
  - **Аудит полноты данных:** автоматическое выявление отсутствующих паспортных полей (диапазон, погрешность, питание, интерфейс, условия среды) с рекомендациями контент-менеджеру.
  - **Контур защиты от галлюцинаций (Zero-Hallucination Guardrail):** детерминированная верификация числовых значений и параметров против исходных данных. Если характеристика отсутствует во входе - выводится отметка `«данных нет»`.
- **Удобство для контент-менеджера:** экспорт и копирование в 1 клик в форматах **Markdown**, **JSON** и визуальной HTML-карточки.

## 3. Быстрый старт и запуск

### Требования
- Python 3.9+ (проверено на Python 3.10 – 3.14)
- Git

### Шаг 1. Клонирование и установка зависимостей
```bash
git clone https://github.com/smolnikov-k/souz-pribor-ai-card-generator.git
cd souz-pribor-ai-card-generator

# Создание и активация виртуального окружения
python3 -m venv venv
source venv/bin/activate  # На Windows: venv\Scripts\activate

# Установка зависимостей
pip install -r requirements.txt
```

### Шаг 2. Настройка окружения (опционально)
Если вы хотите использовать внешнюю LLM (например, OpenAI gpt-4o-mini или Groq):
```bash
cp .env.example .env
# Отредактируйте .env, указав свой OPENAI_API_KEY или GROQ_API_KEY
```
> **Примечание:** Если `.env` не создан или ключ не указан, сервис **автоматически работает в быстром офлайн-режиме**, не требуя внешних API.

### Шаг 3. Запуск веб-интерфейса
```bash
python run.py
```
После запуска откройте в браузере: **http://localhost:8000**

В интерфейсе доступны:
- Кнопки быстрой загрузки реальных товаров из каталога «СОЮЗ-ПРИБОР» (**Testo 510**, **ОВЕН МК110**, **Неполные данные**).
- Интерактивный счетчик символов SEO-описания (норма 800-1200) и заголовка (до 70 символов).
- Переключение между визуальной карточкой, Markdown и сырым JSON.
- Кнопка копирования результата в один клик.

## 4. Использование через CLI

Для пакетной генерации или интеграции в скрипты предусмотрен CLI-модуль `src.cli`:

```bash
# Обработать все тестовые товары и сохранить результаты в папку examples/
python -m src.cli --run-all-samples

# Обработать конкретный файл
python -m src.cli --input data/samples/sample_1_testo_510.json --output examples/

# Принудительный офлайн-режим (без обращения к сети)
python -m src.cli --input data/samples/sample_2_owen_mk110.json --force-offline
```

## 6. Описание промптов и инженерных решений

### 1. Стратегия промптинга (Prompt Engineering)
- **Ролевое позиционирование:** модель инструктируется как ведущий технический редактор КИПиА каталога «СОЮЗ-ПРИБОР».
- **Запрет на галлюцинации (Grounding):** в системный промпт заложен жесткий императив: все технические параметры должны браться *исключительно* из входного JSON. Любая отсутствующая характеристика маркируется как `«данных нет»`.
- **Строгий JSON-контракт:** вызов модели осуществляется с `response_format: {"type": "json_object"}` и низкой температурой (`temperature: 0.2`), что минимизирует дисперсию и гарантирует валидность схемы.
- **Управление длиной описания:** промпт явно задает коридор в 800–1200 символов, а программный слой Pydantic и валидатор проверяют фактический размер.

### 2. Защита от выдумывания характеристик (Anti-Hallucination Guardrail)
В промышленности выдуманная погрешность (например, 0.5% вместо 1.5%) или выдуманное рабочее давление ведут к ошибкам при закупках и авариям на объектах.
Для защиты реализован класс `AntiHallucinationGuardrail` (`src/audit.py`):
- Парсит все числовые значения, диапазоны и метрологические токены в сгенерированной таблице характеристик.
- Сверяет их с исходным сырым текстом и словарём `specs`.
- При обнаружении несоответствий помечает карточку и выводит отчет контент-менеджеру.

### 3. Обработка неполных данных
Модуль `audit_product_data` проверяет наличие обязательных для КИПиА атрибутов:
1. Завод-изготовитель (бренд).
2. Диапазон измерений / входная шкала.
3. Класс точности / предел допустимой погрешности.
4. Выходные сигналы и коммуникационные интерфейсы (RS-485, 4-20 мА, реле).
5. Параметры питания (220 В, 24 В, батареи).
6. Условия эксплуатации и климатическое исполнение.
7. Степень защиты оболочки (IP).

Если критических параметров не хватает, карточка генерируется с предупреждающим баннером, а контент-менеджер видит список недостающих полей для запроса у поставщика.

## 7. Запуск тестов

В проекте настроен полный набор автотестов на `pytest` и `fastapi.testclient`:

```bash
python3 -m pytest tests/ -v
```

Тесты проверяют:
- Валидацию входных Pydantic-моделей (обработка пустых значений).
- Соблюдение лимита длины SEO Title (<= 70 символов).
- Соблюдение коридора длины SEO-описания (800–1200 символов).
- Корректность количества поисковых запросов (3–5).
- Детекцию пропусков в неполных входных данных.
- Работу детерминированного Guardrail против галлюцинаций.
- Работоспособность API эндпоинтов `/api/health`, `/api/samples` и `/api/generate`.

## 8. Ограничения решения и вектор развития (Roadmap)

### Текущие ограничения (в рамках MVP)
- Обработка выполняется поштучно или пакетно из JSON-файлов (без прямого подключения к боевой СУБД 1С / Bitrix).
- Ввод паспорта прибора ограничен текстовым фрагментом (не включает прямой парсинг 50-страничных PDF со сканами чертежей).

### Что можно улучшить при масштабировании в продакшене
1. **Мультимодальный OCR/VLM пайплайн:** интеграция разбора PDF-паспортов и сборочных чертежей через Vision-LLM (разбор таблиц исполнений, схем подключения и габаритных чертежей).
2. **Интеграция с каталогом и 1С / Bitrix Commerce:** коннектор к YML/XML фидам поставщиков и автоматический импорт готовых карточек в интернет-магазин через REST API.
3. **Векторный RAG по ГОСТам и нормативной базе:** семантический поиск по реестру СИ (Госреестр средств измерений) и ГОСТам для автоматического заполнения межповерочного интервала и сертификатов типа СИ.
4. **Дообучение компактной модели (SLM 2B-3B параметров):** fine-tuning специализированной модели (LoRA / QLoRA) на корпусе 50 000+ карточек КИПиА каталога «СОЮЗ-ПРИБОР» для автономной локальной генерации на серверах компании с нулевыми затратами на внешние API.
